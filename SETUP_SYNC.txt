Dayflow: 계정 생성과 기기 간 동기화 설정

중요
- 계정 기반 동기화에는 클라우드 백엔드가 필요합니다. 이 앱은 Supabase Auth + Database를 사용하도록 준비되어 있습니다.
- 이 ZIP을 HTTPS 정적 호스팅에 올리고, 아래 설정을 한 번 완료해야 회원가입/로그인 및 여러 기기 동기화가 실제로 작동합니다.
- Supabase의 anon/publishable key만 웹 앱에 넣으세요. service_role key, 비밀번호, 비밀 키는 절대 넣지 마세요.

설정 방법
1. https://supabase.com 에서 프로젝트를 만듭니다.
2. 프로젝트의 Connect/API 설정에서 Project URL과 anon 또는 publishable key를 확인합니다.
3. Supabase SQL Editor에서 아래 SQL을 실행합니다.

create table if not exists public.dayflow_data (
  user_id uuid primary key references auth.users(id) on delete cascade,
  payload jsonb not null default '{}'::jsonb,
  updated_at timestamptz not null default now()
);

alter table public.dayflow_data enable row level security;

create policy "Users can read own Dayflow data"
on public.dayflow_data for select
to authenticated
using (auth.uid() = user_id);

create policy "Users can insert own Dayflow data"
on public.dayflow_data for insert
to authenticated
with check (auth.uid() = user_id);

create policy "Users can update own Dayflow data"
on public.dayflow_data for update
to authenticated
using (auth.uid() = user_id)
with check (auth.uid() = user_id);

4. 이 폴더 전체를 HTTPS 정적 호스팅(예: GitHub Pages, Netlify 등)에 올립니다.
5. 사이트를 열고 ‘Supabase Project URL’과 ‘anon / publishable key’를 입력한 뒤 ‘클라우드 연결’을 누릅니다.
6. 이메일과 비밀번호로 계정을 만들거나 로그인합니다. 이메일 인증이 켜져 있으면 받은 편지함에서 인증을 완료한 뒤 로그인하세요.
7. 다른 기기에서도 같은 사이트를 열고 같은 계정으로 로그인한 뒤 ‘지금 동기화’를 누르면 됩니다.

동기화 동작
- 일정/루틴/평가 알림을 클라우드의 계정별 한 payload로 저장합니다.
- 로그인 직후 클라우드 데이터가 로컬 데이터보다 우선 적용됩니다.
- 이 간단한 버전은 실시간 충돌 해결 기능이 없습니다. 여러 기기에서 동시에 수정하면 마지막 저장 내용이 우선할 수 있으므로, 동시에 편집하지 않는 것을 권장합니다.
- 계정별 데이터는 RLS 정책으로 본인만 읽고 쓸 수 있도록 제한합니다.

과제 자동 분배
- 총 과제량, 단위, 시작 날짜, 마감 날짜를 입력하면 날짜별로 가능한 한 균등하게 나눕니다.
- 예: 20 pages / 5 days -> 4 pages per day.
- 실제 난이도나 과목별 소요 시간을 자동 판단하는 AI 기능은 아니므로, 미리보기 결과를 확인하고 필요하면 하루 예상 시간을 조정하세요.


자동 업데이트와 데이터 보존 설정

자동 배포
1. GitHub에서 새 repository를 만들고 이 폴더 안의 파일을 모두 업로드합니다. .github/workflows/deploy.yml 파일도 포함해야 합니다.
2. Repository Settings > Pages에서 Build and deployment source를 GitHub Actions로 설정합니다.
3. main 브랜치에 변경사항을 push할 때마다 사이트가 자동 배포됩니다. 이 대화에서 만든 파일 자체가 이미 공개 사이트에 자동으로 연결되는 것은 아니며, 먼저 GitHub 저장소와 Pages를 한 번 연결해야 합니다.
4. 이후 플래너를 개선할 때 수정된 파일을 같은 저장소에 반영하면 자동으로 배포됩니다. 방문자의 브라우저는 새 버전을 감지해 업데이트를 적용합니다.

데이터 보호
- 앱 버전 업데이트는 localStorage의 dayflowTasks/dayflowRoutines/dayflowReminders 키를 삭제하지 않습니다.
- 앱은 데이터 스키마 버전을 관리하며, 추후 데이터 구조가 바뀌면 마이그레이션을 추가해야 합니다.
- 설정 메뉴의 '백업 파일 다운로드'로 JSON 백업을 주기적으로 저장하고, 필요할 때 '백업 파일 복원'을 사용하세요.
- 브라우저 저장 공간은 브라우저/도메인별로 구분됩니다. 사이트 도메인을 바꾸거나 브라우저 데이터를 지우면 로컬 데이터가 자동으로 이동하지 않습니다.
- 클라우드 동기화를 설정한 계정은 클라우드에도 데이터를 보관할 수 있습니다. 다만 동시에 수정하면 마지막 저장이 우선할 수 있으니, 중요한 변경 전후에는 백업을 권장합니다.
